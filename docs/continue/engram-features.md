## 2. Funcionalidades observables (F01..F44)

### Escritura de memorias

**F01 mem_save: guardar observacion** - `internal/mcp/mcp.go:541-612` (schema), `1569-1768` (handler), `internal/store/store.go:4245-4430`.
Entrada: `title` (obligatorio), `content` (o alias `observation`; obligatorio), `type` (def. `manual`), `session_id`, `scope` (def. `project`), `topic_key`, `project`, `project_choice_reason`, `recovery_token`, `capture_prompt` (bool, def. true; si no es bool -> error "capture_prompt must be a boolean").
Reglas: titulo vacio tras trim -> error `Failed to save: ...` (mcp.go:1589; store 4260); contenido vacio -> error (1582, store 4263). Strip `<private>` (F05). Truncado a 50000 bytes (F06). Orden de decision: (1) si hay `operation_id` ya registrado con mismo fingerprint -> replay sin mutar; con otro fingerprint -> `ErrObservationOperationConflict` (4280-4306); (2) si `topic_key` -> upsert (F02); (3) si no, dedupe por hash (F03); (4) si no, INSERT con `revision_count=1`, `duplicate_count=1`, `sync_id=obs-...`, y `review_after` si el tipo tiene decay (F27).
Salida (texto + JSON): `Memory saved: "<title>" (<type>)`, si no se paso topic_key anade `Suggested topic_key: ...` (1689), avisos de truncado, de ruta absoluta (`absolutePathWarning` mcp.go:94), de normalizacion de proyecto, de proyecto similar (F19); sobre JSON con `id`, `sync_id`, `state`, `review_after`, `judgment_required`, `candidates[]` (F31). Tras guardar, tambien captura el prompt actual si hay contexto (F23).
PORTABLE (nucleo). Parte de proyecto/sesion implicita es ADAPTABLE (en Android el "proyecto" es un workspace/agente).

**F02 Upsert por topic_key** - store.go:4317-4373.
Si `topic_key` normalizado no es vacio: busca la fila viva mas reciente con mismo `topic_key`, mismo `project` (ifnull) y mismo `scope`, `ORDER BY updated_at DESC, created_at DESC LIMIT 1`. Si existe: captura version previa en `observation_versions`, hace UPDATE in situ de `session_id,type,title,content,tool_name,topic_key,normalized_hash`, `revision_count+1`, `last_seen_at=updated_at=now`. NO incrementa `duplicate_count`. Temas distintos no se pisan. Normalizacion de clave (13646-13656): trim, minusculas, espacios internos -> `-`, max 120 chars. PORTABLE.

**F03 Dedupe por hash de contenido en ventana** - store.go:4375-4410, `hashNormalized` 13665, `dedupeWindowExpression` 13671.
Hash = SHA-256 hex de `lower(join(fields(content)," "))` (colapsa espacios, insensible a mayusculas). Coincide si mismo `normalized_hash` + `project` + `scope` + `type` + `title` + `deleted_at IS NULL` + `created_at >= now-15min` (minimo 1 min, defecto 15). Accion: `duplicate_count+1`, `last_seen_at=updated_at=now`; NO crea fila, devuelve el id existente. Solo se evalua si no hay topic_key o no encontro fila. PORTABLE.

**F04 Tipos de observacion** - tipos libres de texto. Sugeridos en schema/protocolo: decision, architecture, bugfix, pattern, config, discovery, learning, preference, manual (defecto), session_summary (generado), passive (F24). La busqueda acepta ademas tool_use, file_change, command, file_read, search (mcp.go:495). Solo los tipos de la tabla de decay (F27) tienen `review_after`. PORTABLE.

**F05 Etiquetas de privacidad `<private>...</private>`** - store.go:13720-13730 (`(?is)<private>.*?</private>` -> `[REDACTED]`, luego trim). Se aplica a titulo, contenido, prompts y find/replace antes de persistir (4253-4254, 4711, 5378, 5481). Titulo que queda vacio tras redactar -> rechazado. PORTABLE (trivial).

**F06 Limite de tamano y truncado** - store.go:4961-4983. >50000 bytes: corta en frontera UTF-8 y anade `... [truncated]`; devuelve metadatos `{OriginalBytes, LimitBytes, Truncated}` y el handler anade aviso (mcp.go `truncationWarning` 87). PORTABLE.

**F07 mem_update: edicion parcial por id** - mcp.go:617-654, 1789-1848; store.go:5326-5450.
Entrada: `id`, `expected_project` (obligatorio, comprobado atomicamente contra el dueno), y al menos uno de `title`,`content`,`find`+`replace`,`type`,`scope`,`topic_key`. Reglas: `find` y `replace` van en par (5331); `content` y find/replace son excluyentes (5334); find/replace es literal, sensible a mayusculas, reemplaza todas las apariciones, con prueba de crecimiento para no exceder 50000 (5455-5490) y no-op si no hay coincidencias; `project` es inmutable (5394-5399); se captura version previa solo si cambia titulo/contenido (5410). Siempre `revision_count+1`, recalcula `normalized_hash`. NO recalcula `review_after`. PORTABLE.

**F08 mem_delete soft/hard** - mcp.go:705-724, 1956-1978; store.go:5505-5598. `id`, `expected_project`, `hard_delete` (def. false). Soft: `deleted_at=now` (sale del FTS por trigger; versiones y relaciones se conservan). Hard: borra fila y marca las `memory_relations` que la referencian como `judgment_status='orphaned'` (nunca borra relaciones, 5553-5562). Perfil admin (no entra en perfil agent). PORTABLE.

**F09 mem_pin / mem_unpin** - mcp.go:757-787, 1507-1540; store.go:4503-4528. Solo `UPDATE pinned=0/1 WHERE deleted_at IS NULL`; devuelve JSON `{result:"Memory #N pinned|unpinned", id, sync_id, pinned}`. Estado local al dispositivo, no se sincroniza ni exporta como mutacion. Efectos: seccion `### Pinned` primero en contexto (F13) y +0.10 al ranking (F11). Sin limite de numero de pins en el store; el contexto MCP limita a 20 pinned (mcp.go:2066). PORTABLE.

**F10 mem_suggest_topic_key** - mcp.go:677-700, 1770-1787; store.go:13522-13630. Solo lectura. Familia inferida del `type` (architecture/design/adr/refactor -> `architecture`; bug/bugfix/fix/incident/hotfix -> `bug`; decision; pattern/convention/guideline -> `pattern`; config/setup/infra/ci -> `config`; discovery/investigation/root_cause -> `discovery`; learning; session_summary -> `session`) o, si el tipo no ayuda, por palabras clave en `titulo+contenido` (bug/fix/panic/error/crash..., architecture/design/..., decision/tradeoff..., pattern/naming..., config/docker..., discovery/found..., learned). Segmento = titulo normalizado (`[^a-z0-9]+`->`-`, max 100), si vacio, primeras 8 palabras del contenido, si vacio `general`; quita prefijo `<familia>-`; si el origen tiene caracteres no ASCII anade sufijo `-u-<12hex sha256>`. Resultado `familia/segmento`. Requiere titulo o contenido. PORTABLE (algoritmo pequeno y explicito).

### Busqueda y lectura (divulgacion progresiva)

**F11 mem_search: FTS5 con ranking compuesto** - mcp.go:481-518, 1315-1505; store.go:5718-5866 (completa), 5870-5993 (previews, la que usa MCP), 6013-6069.
Entrada: `query` (obligatorio), `type`, `project`, `all_projects`, `scope`, `match_mode` (`all` defecto = AND | `any` = OR; otro valor -> error), `response_format` (`compact`), `limit` (def. 10, max 20).
Algoritmo: (a) si la query contiene `/`, primero filas con `topic_key = query` exacto (rank -1000, ordenadas por `updated_at DESC`) y luego FTS sin duplicados (5743-5797); (b) si algun termino tiene <3 runas (`hasShortFTSTerm` 6074; el tokenizador trigram no puede) se usa fallback LIKE escapado sobre title/content/tool_name/type/project/topic_key, AND u OR segun match_mode, orden `updated_at DESC` (6111-6146); (c) si no, FTS5: `all` -> cada palabra entre comillas dobles (comillas internas duplicadas) unidas por espacio (`sanitizeFTS` 13734); `any` -> mismas palabras unidas por ` OR ` (`sanitizeFTSCandidates` relations.go:1163). Orden SQL: `bm25(fts,5.0,1.0,0,0,0,3.0) * (1 + 0.10*pinned + 0.06*(1/(1+dias_desde_last_seen/30)) + 0.04*((rev+dup)/(rev+dup+4)))` ASC (bm25 es negativo: mas negativo = mejor), desempate por sync_id y id (6031-6067). Filtros: `deleted_at IS NULL`, tipo, `LOWER(project)=normalizado`, scope. Si `scope=personal` y sin proyecto explicito se ignora el proyecto (REQ-391, mcp.go:1359). `all_projects=true` ignora proyecto.
Salida: bloque de texto `[i] #id (type) — title` + preview de 300 chars (`substr(content,1,300)`, marca ` [preview]` si trunco) + fecha local + `| project: x | scope: y | state: needs_review` (si `review_after` vencido); nota final `Results above are previews (300 chars). To read the full content ... mem_get_observation(id: <ID>)`; JSON estructurado en `results`. Con `response_format=compact`: `Found N memories.` + `results[]` con `preview`, `truncated`, `relations` (search_projection.go:33-47). Vacio: `No memories found for: "<q>"`. Anexa nudge (F22). Anotaciones de relaciones por resultado: `supersedes: #id (titulo)`, `superseded_by: #id (titulo)`, `conflicts: #id (titulo)`, `conflict: contested by #<id> (pending)`, "(deleted)" si el extremo no existe (mcp.go:1442-1488).
PORTABLE (FTS5 trigram disponible en SQLite de Android 11+/bundled; si no, ADAPTABLE con LIKE). La formula de ranking es reimplementable en SQL.

### Captura pasiva

**F24 mem_capture_passive** - mcp.go:1011-1039, 2628-2676; store.go:13768-13900. Entrada `content`, `session_id`, `source` (def. `mcp-passive`). Extrae items de la ULTIMA seccion cuyo encabezado case `(?im)^#{2,3}\s+(?:Aprendizajes(?:\s+Clave)?|Key\s+Learnings?|Learnings?):?\s*$`; la seccion termina en el siguiente `\n#{1,3} `. Items: primero numerados `^\s*\d+[.)]\s+`, si ninguno valido, vinietas `^\s*[-*]\s+`. Limpia markdown (negrita, codigo inline, cursiva, espacios). Descarta items con <20 caracteres o <4 palabras. ## 3. Flujos clave

### 3.1 Guardar con dedupe/upsert
1. Entrada `mem_save(title, content, type?, scope?, topic_key?, project?, session_id?)`.
2. Validar titulo/contenido no vacios -> resolver proyecto (F19) -> resolver sesion (explicita o `manual-save-{proyecto}`) -> crear sesion implicita si no existe.
3. Strip `<private>` y truncar a 50000 bytes; `norm_hash = sha256(lower(collapse_ws(content)))`.
4. Dentro de una transaccion: [idempotencia por operation_id] -> [si topic_key: buscar fila viva (topic_key, project, scope) -> snapshot a `observation_versions` + UPDATE, `revision_count+1`] -> [si no: buscar duplicado (hash, project, scope, type, title, <15 min) -> `duplicate_count+1`] -> [si no: INSERT con `review_after` por tipo]. Cada rama encola mutacion de sync (omitible on-device).
5. Fuera de la transaccion: capturar prompt actual (F23), registrar guardado para el nudge, `FindCandidates` (F31), responder con sobre JSON (`id, sync_id, state, review_after, judgment_required, candidates[]`).

### 3.2 Buscar con divulgacion progresiva
`mem_context` (barato, al inicio) -> `mem_search(query)` devuelve previews de 300 chars con `#id`, tipo, fecha, proyecto, scope, estado y anotaciones de relaciones -> si hace falta vecindad `mem_timeline(observation_id)` -> `mem_get_observation(id, include_history?)` para el contenido completo. Busquedas con `topic_key` exacto (query con `/`) devuelven primero la fila del tema. `match_mode=any` para ampliar recall; `all_projects=true` para busqueda cruzada.

### 3.3 Juicio de conflictos
`mem_save` -> candidatos `pending` (max 3, relevancia por titulo/topic_key) -> el agente lee cada candidato (mem_get_observation) -> `mem_judge`/`mem_judge_many` con una de 6 relaciones, `reason`, `evidence`, `confidence` -> fila `judged`. Preguntar al usuario si confianza <0.7 o (supersedes|conflicts_with sobre architecture|policy|decision). El veredicto aparece despues como anotacion en `mem_search` (`supersedes:`, `superseded_by:`, `conflicts:`). `mem_compare` crea o actualiza un veredicto sobre un par arbitrario sin pasar por pending. Hard delete deja la relacion `orphaned` (auditoria).

### 3.4 Resumen de sesion
Antes de decir "done": `mem_session_summary(content)` con las 6 secciones -> observacion `session_summary` -> (host) `mem_session_end(id)`. Alternativa atomica: `mem_session_finalize`. En `mem_context` el resumen de las ultimas 5 sesiones aparece truncado a 200 chars.

### 3.5 Contexto al inicio y tras compactacion
Inicio: el hook SessionStart registra la sesion e inyecta el contexto previo (equivale a `mem_context`); primer prompt: instruccion para cargar tools y reutilizar el contexto ya inyectado, llamando `mem_context` solo si falto. Tras compactacion: primera accion obligatoria `mem_session_summary` con el resumen compactado, luego `mem_context` (setup.go:284-289; plugins/opencode/engram.ts; docs/PLUGINS.md:209-218).

### 3.6 Captura pasiva
El agente (o un hook SubagentStop/session-end) pasa texto con `## Key Learnings:` a `mem_capture_passive`; se extraen items (F24), se deduplican por hash y se guardan como `passive`. Es red de seguridad; `mem_save` es el camino principal. Engram NO captura llamadas a herramientas en bruto (DOCS.md:1979-1981, decision deliberada de calidad/ruido).

## 4. Instrucciones/prompts que Engram da al agente (texto fuente)

Fuente unica del protocolo largo: `internal/setup/setup.go:153-291` (`memoryProtocolMarkdown`), replicado en `DOCS.md:1676-1835`, `plugin/claude-code/skills/memory/SKILL.md`, `plugin/codex/skills/memory/SKILL.md` y `internal/setup/plugins/opencode/engram.ts`. Instrucciones del servidor MCP: `internal/mcp/mcp.go:373-427`. Resumen fiel (parafraseado salvo lo entrecomillado):

**Instrucciones MCP (initialize)**: "Engram provides persistent memory that survives across sessions and compactions." Lista CORE TOOLS (mem_save "save decisions, bugs, discoveries, conventions PROACTIVELY (do not wait to be asked)"; mem_search; mem_context "call at session start or after compaction"; mem_session_summary "MANDATORY before saying done"; mem_get_observation; mem_save_prompt; mem_current_project "recommended first call"; mem_judge; mem_compare) y DEFERRED TOOLS (mem_update, mem_review, mem_pin, mem_unpin, mem_suggest_topic_key, mem_session_start/end, mem_doctor, mem_capture_passive, ...). Regla: "PROACTIVE SAVE RULE: Call mem_save immediately after ANY decision, bug fix, discovery, or convention — not just when asked." Seccion DELIVERY GUARANTEE y CONFLICT SURFACING (texto de F34; "never reuse the top-level judgment_id").

**Protocolo (resumen de reglas)**:
1. Disparadores de guardado OBLIGATORIOS sin que el usuario lo pida: tras decisiones/convenciones (arquitectura, convencion, cambio de flujo, eleccion de libreria con tradeoffs); tras completar trabajo (bugfix con causa raiz, feature con enfoque no obvio, artefactos Notion/Jira/GitHub significativos, cambio de config); tras descubrimientos (gotchas, patrones, preferencia/restriccion del usuario); tras confirmacion o rechazo del usuario ("go with that", "sounds good", "agreed", "no, better X", "I prefer X over Y", o equivalentes en su idioma; tambien cuando una discusion concluye con una direccion clara aunque la propusiera el agente).
2. Autoverificacion tras CADA tarea: "Did I or the user just make a decision, confirm a recommendation, express a preference, fix a bug, learn something non-obvious, or establish a convention? If yes, call mem_save NOW."
3. Formato de `mem_save`: title = verbo + que, corto y buscable (ej. "Fixed N+1 query in UserList", "Chose Zustand over Redux"); type: bugfix|decision|architecture|discovery|pattern|config|preference; scope: project (def.)|personal|global; topic_key opcional pero recomendado para temas que evolucionan (ej. `architecture/auth-model`); content = `**What**` (una frase), `**Why**`, `**Where**` (archivos), `**Learned**` (omitir si nada).
4. Reglas de topic_key: temas distintos NO se pisan; mismo tema que evoluciona -> mismo topic_key (upsert); si hay duda -> `mem_suggest_topic_key` y reutilizarlo; si se conoce el id exacto -> `mem_update`.
5. Cuando buscar: ante "remember/recall/what did we do/how did we solve" (o equivalente): primero `mem_context`, luego `mem_search`, luego `mem_get_observation`. Proactivamente al empezar algo que pudo hacerse antes, ante un tema sin contexto, y si el PRIMER mensaje del usuario menciona proyecto/feature/problema (buscar con palabras clave antes de responder).
6. DELIVERY GUARANTEE: las operaciones de memoria son contabilidad interna, nunca la respuesta; completarlas antes de componer la respuesta final, enviar la respuesta completa como ultimo mensaje sin tool calls posteriores; si la memoria falla, igualmente responder.
7. Cierre de sesion OBLIGATORIO antes de "done": `mem_session_summary` con `## Goal / ## Instructions / ## Discoveries / ## Accomplished / ## Next Steps / ## Relevant Files`. "This is NOT OPTIONAL. If you skip this, the next session starts blind." Gemini: despues llamar `mem_session_end`, nunca antes del summary.
8. Captura pasiva: al terminar tarea/subtarea incluir `## Key Learnings:` con items numerados (ej. "bcrypt cost=12 is the right balance..."); es red de seguridad, no sustituye a `mem_save`.
9. Tras compactacion o si se ve "FIRST ACTION REQUIRED": 1) `mem_session_summary` con el resumen compactado, 2) `mem_context`, 3) solo entonces continuar. Prompt de compactacion de Codex (setup.go:301-314): anteponer exactamente `FIRST ACTION REQUIRED: Call mem_session_summary with the content of this compacted summary before doing anything else, then call mem_context.` y resumir Goal, descubrimientos/decisiones, trabajo hecho, siguientes pasos, archivos.
10. Descripciones de tool relevantes: mem_save ("Call this PROACTIVELY after completing significant work — don't wait to be asked", plantilla What/Why/Where/Learned con ejemplos), mem_session_summary (guias: conciso, Discoveries es la seccion mas valiosa, Relevant Files solo los significativos), mem_judge ("WHEN TO CALL: After mem_save returns judgment_required=true..."), mem_compare ("You do the judgment; mem_compare records it").
11. Recordatorios en runtime: nudge de 10 min (F22) y `Suggested topic_key:` tras guardar sin clave.
