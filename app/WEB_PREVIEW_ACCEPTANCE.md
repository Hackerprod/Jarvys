# Web preview physical-device acceptance (UX22/UX28)

Host tests do not run Chromium. This checklist remains unverified until executed with the delivered Jarvys APK on actual Android WebView.

1. Deliver an HTML page containing long vertical content, a horizontal overflow region, an editable input, an ordinary local page link, a local CSS file, a JavaScript button and a local image. Repeat with explicit `preview_workspace` path under `/project/`. Confirm the thumbnail itself opens the internal preview, no textual View in Jarvys button appears, and Download/Share are separate icon actions.
2. Open the preview. Scroll slowly and fling vertically, diagonally and horizontally from the left edge and center. The page should scroll naturally and the app drawer must stay closed. Pinch with two fingers, cancel a gesture, tap and select text. Record WebView version/device and frame traces before making any performance assertion.
3. Focus the HTML input, type with the real soft keyboard, select text, dismiss the keyboard and rotate. Confirm content remains usable. Native history/URL/scroll restoration is bounded; arbitrary JavaScript heap/form state after process death is not promised.
4. Follow the local page link and fragment. Trigger app-state changes while the page stays open. The preview must not jump to index.html on ordinary recomposition. Press the native Back control to return to the same chat; reopen and check navigation/reading position. Repeat Activity recreation and process recreation separately.
5. Edit, rename and remove the original project files after delivery. The original card must still serve the captured bytes. Deliver the changed page again and confirm its new dependency snapshot does not replace the old card. An old single-file HTML attachment must show the missing-linked-assets notice.
6. Test a missing stylesheet, dynamic fetch, external image/CDN URL, malformed encoded path, a symlink and an above-root reference. The preview must fail safely or show an incomplete-resource notice. It must never expose another chat, private app files or a native JavaScript bridge.
7. Confirm external URL navigation, `file:`, `content:`, `intent:`, automatic downloads, forms, frames and workers do not launch external apps or access private data. Ordinary scripts are enabled. The provider-dependent Connection-Allowlist header is intended to block WebRTC/ICE on supporting providers; this remains unverified on Android, and older providers can ignore it. Test that separately before any isolation claim.
8. Use Download on the HTML card and verify the original file in OS Downloads. Share only when explicitly pressed. Previewing must not open the APK installer, execute an APK, upload the page or change account/device permissions.
9. Repeat in English/Spanish, light/dark, narrow phone width, large text, TalkBack and reduced motion. Check visible and spoken labels, minimum touch targets, Back priority, keyboard obstruction and no clipped actions.


## UX28 thumbnail acceptance

10. Before opening the page, inspect its real static thumbnail with local CSS, fonts and images. Check that pixels correspond to the delivered immutable snapshot, not an illustration or newer workspace. Repeat HTML and CSS-only changes and reopen both old and new cards. Record actual device/WebView version and screenshots.
11. Try a JavaScript-only application and an empty page. Scripts must not execute during chat rendering; the unavailable placeholder must be honest and remain tappable; no static-caption footer should appear. Opening the interactive page may execute its existing permitted scripts, but entered data or navigated pages must not become thumbnail screenshots.
12. Observe network traffic while cards render, including external image/font URLs, fetch/WebSocket/WebRTC code, DNS-prefetch/preconnect links, SVG references and meta refresh. Confirm automatic thumbnails do not execute scripts or perform external resource/network activity. No airtight network claim is made before this check.
13. Scroll rapidly through many HTML cards, background/foreground, rotate, switch chats, delete a chat during rendering and reopen. Check one bounded renderer, prompt cancellation/cleanup, no visible hidden WebView, no input interception, no stale image or recreated deleted cache. Capture memory/frame traces before performance claims.
14. At narrow width and 200% text in English/Spanish and both themes, use TalkBack to open the thumbnail and activate Download/Share; test busy cancellation, permission denial, saved-file Open and long names. Each action must keep a distinct spoken label and at least 48 dp target. Non-HTML files and unavailable originals remain correct.

## UX33 full-card presentation

15. Verify a single outer rounded border, with actual page pixels reaching every inner edge. There is no file header, filename, size/MIME row, inner frame, divider or static-caption footer. The preview stays 3:2 in both themes, English/Spanish and at 200% text. While metadata or pixels load, no removed header flashes.
16. Inspect light, dark and detailed pages behind the bottom-up gradient. Download and Share retain their 22 dp glyphs and 64 dp center spacing; visible circles are 40 dp while touch targets are at least 48 dp. Tap glyphs and the invisible target rim, verify disabled saving taps never open the page, and tap elsewhere in the gradient or between actions to open the internal preview. Check Cancel, permission denial, retry and saved Open without overlapping controls.
17. Check loading, empty/JavaScript-only pages and renderer failure: localized status remains legible above actions. Missing originals or wrong-conversation artifacts must not expose preview/export access. Recheck scroll, reopen, lifecycle cancellation and deletion. Host fixture captures certify presentation only, not actual Chromium rendering, physical touch dispatch or observed network behavior.

## UX39 provider-dependent WebRTC/ICE hardening

18. Record the Android version, exact active WebView package/version and APK source/hash. Run through the actual Jarvys preview route with synthetic immutable HTML; a desktop Chrome response or Robolectric header assertion does not validate `WebResourceResponse` ingestion on Android. WebView 152 is the published shipping milestone. Test at least a supporting provider and a retained older/unsupported provider; report them separately. Do not change provider flags or device network settings as an implicit part of acceptance.
19. Verify local CSS, ordinary and module JavaScript, image/font resources, click handlers, editable inputs, DOM storage, local links/fragments and restored local navigation. Check all success and failure responses retain the appropriate complete policy. A missing file or denied method must not become an unprotected same-origin document. Confirm frames, popup windows, workers, external URL loads, private paths and cross-conversation resources remain unavailable.
20. In a disposable synthetic harness, compare the existing CSP without Connection-Allowlist against the same page with `Connection-Allowlist: (response-origin); webrtc=block; redirects=block`. Use an explicitly authorized local STUN/TURN sink and independent packet observation; never default to public third-party ICE endpoints or real user content. The control must demonstrate observable permitted ICE traffic, while the hardened case must emit none to the tested endpoints. If both fail, report the test as inconclusive. Check candidate-pool gathering, offer/data channel creation, added remote candidates, `setConfiguration` and ICE restart. Native failure may be asynchronous; constructor success alone is not proof of an allowed connection.
21. Include malformed-header controls and attempted fresh contexts (`about:blank`, `srcdoc`, blob and data URLs, nested frames and local navigation), while retaining the existing frame/window/worker restrictions. Check DNS-prefetch/preconnect and other relevant network paths separately. Request/console logs alone do not establish zero packets, and this scoped policy does not certify whole-device or unrelated app traffic. No external reporting endpoint should be configured by the preview.
22. Older providers must still preserve the interactive preview contract and fail-closed local resource boundary, without reporting their WebRTC risk as resolved. Keep the remaining network acceptance item open until the measured provider/device matrix supports a bounded claim. The initial host Chromium 154 experiment was blocked before loading a page by a process-socket permission failure; it provides no observed enforcement or compatibility result.

## UX41 mobile viewport acceptance

23. Use the actual updated Jarvys APK and record its hash/version plus Android and active WebView package/version. Compare synthetic pages with: authored `width=device-width, initial-scale=1`; no viewport; explicit `width=1280`; duplicated/empty/malformed viewport; responsive CSS; and intentional fixed-width table/canvas overflow. Exercise both live workspace and immutable delivered-snapshot routes. Keep a pre-change control when available; the user's exact reported HTML has not been reproduced in the host tests.
24. Measure only synthetic layout diagnostics: native WebView available width/height and density; `innerWidth`, document-element `clientWidth`, visualViewport width/height/scale, a known CSS media query, effective UA and viewport declarations. Record screenshots with those metrics at compact and expanded window widths, portrait/landscape, several densities and normal/large system font settings. Do not collect real page text, input values, conversations or storage. The missing-viewport case should start at the available mobile CSS width; authored wide viewports/layouts must retain their intent. Native/visual viewport dimensions are distinct from user zoom.
25. Pinch, scroll horizontally/vertically, select/copy, use buttons/local modules/images, navigate links/fragments and return. Recompose, pause/resume, resize/rotate, close/reopen and switch projects. Check no forced scale reset, unsolicited reload or cross-project state; separately label native history/URL/scroll restoration versus arbitrary form/JavaScript heap survival. Focus an input, type using the real IME, move focus and dismiss it without resetting the user's zoom. Host tests only establish untouched settings/state boundaries, not these physical interactions.
26. Compare original source, captured manifest/member bytes and downloaded HTML before/after opening. Only the supported main-document response may gain one default viewport; explicit viewports, HTML subresource fetches, HEAD and all ordinary assets remain byte-exact. Check UTF-8 BOM, headless fixtures and ordinary inline SVG icons without a viewport; malformed/ambiguous-foreign-content/legacy-encoding/oversized documents can pass through without adaptation and may remain wide. Do not describe these exclusions or fixed-width pages as mobile successes.
27. Recheck all UX39 complete headers, origin/path/manifest denials, no new bridge/permission/network behavior and the older-provider caveat using the original positive/negative controls. The static thumbnail keeps its separate JavaScript-disabled renderer and is not proof of interactive viewport parity. Neither screenshots nor absent console errors certify network isolation.
