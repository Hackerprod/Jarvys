## WebView real de módulos y lienzo

El AVD `JarvysModuleWebView34` (Android 14 / API 34, Google APIs x86_64; System WebView 113.0.5672.136) reprodujo el fallo antes de la corrección. Los diagnósticos instrumentados mostraron `Resource denied: data://no-host ... (main frame)` y HTTP 403. `loadDataWithBaseURL` entrega el documento bootstrap inicial como una carga `data:` aun cuando recibe una base HTTPS; el filtro del runtime aplicaba la allowlist de subrecursos al documento principal y lo bloqueaba antes de cargar `logic/tools.js`. El error CSP aparecía como consecuencia. `blockNetworkLoads` permaneció activo.

El runtime ahora deja pasar una sola carga inicial `data:` de main frame, creada por el propio anfitrión. Los subrecursos y las navegaciones siguientes siguen sujetos al filtro del bundle, la CSP y la red bloqueada. Los mensajes de fallo registran recurso/motivo o el tipo seguro de excepción; consola cruda, parámetros, queries y fragmentos no se conservan.

`WebViewModuleRuntimeInstrumentedTest` ejecuta `create_chart` y `create_presentation` contra los assets de producción en Chromium del sistema, comprueba la entrega del JSON/PPTX y valida miniaturas PNG decodificables de 1280×720 con píxeles no vacíos. `ChatCanvasWebViewInstrumentedTest` carga HTML, CSS y JS de producción con red deshabilitada. Esa prueba encontró además que `canvas.js` no pasaba el objeto global a su factory, lo que causaba un `ReferenceError` al inicializar el scroll; el factory ahora recibe el global.

Estas pruebas usan el AVD y son distintas de los tests JVM/Robolectric. Para instalar el APK debug, que el proyecto produce sin firma, se firmaron copias temporales de los APK en `%LOCALAPPDATA%\Temp`; no se cambió la configuración ni el artefacto firmado del proyecto. No hubo cambios al esquema Room v2.

## Causa raíz del visor Android de presentaciones

El visor en blanco se debía al alto del WebView anfitrión. `createViewerWebView` lo insertaba en `AndroidView` sin `layoutParams`, que recibía `WRAP_CONTENT`; aunque `innerHeight` y `documentElement.clientHeight` indicaban 684 CSS px, el documento calculaba alto cero y las reglas porcentuales/`vh` no tenían un viewport útil. La página quedaba detrás del fondo de Compose. El arreglo asignó `ViewGroup.LayoutParams(MATCH_PARENT, MATCH_PARENT)` al WebView y mantuvo `Modifier.fillMaxSize()` en `AndroidView`. La prueba con el HTML de producción sin parche de altura CSS y la hoja de estilo original del visor chart aisló el problema al layout nativo; no se cambió Kotlin para añadir conocimiento de presentaciones.

Las capturas ADB documentan el estado vacío y la recuperación: [visor vacío antes](../pptx-viewer-eval/captures/android-webview-owner-deck-slide1-before-fix.png), [`100vh` tampoco lo arregla](../pptx-viewer-eval/captures/android-webview-owner-deck-slide1-css-vh-fail.png), [probe con altura forzada](../pptx-viewer-eval/captures/android-webview-owner-deck-slide1-forced-height-probe.png), [deck de tres diapositivas después de `MATCH_PARENT`](../pptx-viewer-eval/captures/android-webview-presentation-three-slides-after-host-match-parent.png), [deck de gráfico y tabla](../pptx-viewer-eval/captures/android-webview-presentation-chart-table-after-host-match-parent.png), [visor de gráfico](../pptx-viewer-eval/captures/android-webview-chart-module-viewer-after-host-match-parent.png) y [fallback al cerrar el renderer](../pptx-viewer-eval/captures/android-webview-renderer-fallback-after-host-match-parent.png). ## P4 autonomy default and Wizard

Modules and actions without an explicit saved choice use the single policy selected in the setup Wizard, which defaults to `ALLOW`. Modules remain in their Modules workspace, outside Connectors; `ConnectorRegistry` and `ActionPolicyDefaults` provide the shared default to those action families. Explicit per-tool choices remain authoritative.

MCP keeps the saved initial policy for each server. `COMMON_DEFAULT` follows the Wizard choice, `EXPLICIT_CURRENT` and `LEGACY_UNKNOWN` use the server's saved value, and `INVALID` fails closed to `DENY`; saved per-tool policies still take precedence. The server editor again exposes the initial-policy selector with Allow, Ask, and Deny. A new server starts at the current Wizard default, and the selection becomes explicit only after the user changes it and confirms Save.

The original coverage is restored in `McpInitialToolPolicyTest`, `McpNavigationQ1Test`, `Ux21ConnectorPermissionInteractionTest`, and `McpActionLeaseIntegrationTest`. The lease test covers both a saved server-level Ask and the additional Wizard Ask fallback without materialized per-tool rows. `SetupWizardPreferencesTest` also verifies that persisted action defaults are read from their owning preferences even when the global preference binding is absent. If the connector policy store fails, the displayed policy remains restricted (`ASK`); action admission still fails closed through its saved snapshot. `AppNavigationBackPolicyTest` lists the workspace-session preview and module-artifact-viewer routes, matching the actual navigation destinations.

## Markdown en streaming con bloques inline

La fuente etiquetada de `multiplatform-markdown-renderer` `0.37.0` confirma que `rememberMarkdownState(content)` crea un estado nuevo al cambiar el contenido; ese estado empieza en `Loading` y se parsea en `Dispatchers.Default`. La opción `immediate = true` llama a `parseBlocking()` durante la composición en el hilo principal. Además, `collectAsState()` todavía entrega el último estado recogido durante el primer frame tras un delta, así que el parseo inmediato no evita por sí mismo el frame de carga. `AssistantMarkdown` usa ahora el parseo asíncrono predeterminado y conserva el último `State.Success` mientras llega el resultado; si el parseo termina en error, muestra el texto como texto plano. Fuentes: [MarkdownState.kt de v0.37.0](https://github.com/mikepenz/multiplatform-markdown-renderer/blob/v0.37.0/multiplatform-markdown-renderer/src/commonMain/kotlin/com/mikepenz/markdown/model/MarkdownState.kt#L34-L64), [Markdown.kt de v0.37.0](https://github.com/mikepenz/multiplatform-markdown-renderer/blob/v0.37.0/multiplatform-markdown-renderer/src/commonMain/kotlin/com/mikepenz/markdown/compose/Markdown.kt#L85-L130).

`AssistantMarkdown` mantiene una única instancia de `MarkdownComponents`; el callback del fence lee `streaming` desde un `CompositionLocal`, evitando cambiar la identidad de componentes al promover el mensaje. `MarkdownFenceSource` determina desde el AST si la cabecera terminó, buscando un hijo EOL o contenido después de `FENCE_LANG`. Durante el stream, los lenguajes registrados permanecen en un placeholder de una sola línea hasta cerrar el fence; los desconocidos usan ese placeholder solo mientras la cabecera sigue incompleta y luego se muestran como código mientras crece su contenido. Los renderers registrados conservan el mismo contenedor al cerrar el fence. El test Compose `assistantMarkdownStreamingRetainsRenderedContentAcrossDeltasAndPromotion` mide carga, placeholder, montajes visuales y de fila, altura intermedia y movimiento de la fila con fences `chart` y `svg`.

`InlineMessageBlocksTest.incompleteSpecialFencesWaitOnlyWhileStreamingAndThenFallBackToCode` cubre una cabecera desconocida incompleta y una completa; `openKotlinFenceUsesCodeInsteadOfAStreamingPlaceholder` comprueba que un fence abierto `kotlin` elige la ruta de código durante el stream. No se debilitó ningún test.

## Contrato del módulo de presentaciones: composicion explícita

`create_presentation` recibe `{ title, theme?, slides: [{ background?, notes?, elements }] }`. El agente declara cada caja en pulgadas sobre `LAYOUT_WIDE` (13.333 × 7.5 in); el handler valida y pasa los elementos a PptxGenJS 4.0.1 sin elegir posiciones. El JSON en `result.content` conserva el id del artefacto y un informe compacto: alturas y líneas de texto, contraste cuando es determinable, y hallazgos de desborde, solape o límites; incluye geometría para los elementos que necesitan revisión. Overflow o solape son feedback y se entrega el PPTX. Entrada inválida se rechaza con diapositiva, índice, tipo y campo.

El contrato Node descomprime el PPTX y comprueba runs, shape, PNG data URL, gráfico y tabla OOXML, notas, coordenadas solicitadas y respuesta de texto. También verifica el contrato existente de un artefacto PPTX y una miniatura PNG de la primera diapositiva. El anfitrión descarta campos superiores fuera de `content`; por eso el informe viaja en el JSON de texto. El canal genérico no entrega bloques de imagen del módulo al modelo, así que no se añadieron miniaturas adicionales ni hoja de contacto. La CSP, el aislamiento, la ruta de artefactos, los permisos y Room v2 se conservan; no hay lógica de presentación en Kotlin.

### Aserciones retiradas, cambiadas y sustituidas

- Se retiraron las expectativas de `title`, `body`, `bullets`, `shapes`, `images`, `chart` y `table` colocados por el módulo. El fixture ahora usa `slides[].elements[]` y compara las cajas de los objetos OOXML con las coordenadas dadas; así se detecta cualquier autolayout.
- Se retiraron expectativas de tipografía o color por rol, título oscuro predeterminado, altura promovida de título, `normAutofit`, márgenes automáticos y una regla fija de interlineado. La composición y tipografía ahora vienen de cada elemento o del tema; los tests verifican el tamaño y color informados solo cuando se solicitaron.
- Se retiraron los errores sintéticos de “texto denso”, “sin espacio visual” y “visual pisa viñeta”. Se sustituyeron por dos resultados exitosos: el caso del dueño (título largo de dos líneas, subtítulo y cuatro viñetas) informa `overflow:true` y el par solapado; la misma diapositiva corregida informa overflow falso y ningún par. Ambos entregan el PPTX.
- Se retiró la colocación automática de tablas bajo gráficos o texto, incluido el espacio inferior obligatorio. El fixture de gráfico+insights y el fixture de tabla declaran cajas independientes; el contrato comprueba esas posiciones en OOXML.
- Los errores de chart vacío, datasets vacíos ignorados, longitudes desiguales y valores no finitos ya no usan el esquema anidado legado ni mensajes recomendando ediciones. Se validan `labels`, `datasets[].values`, longitudes y valores finitos con el índice/tipo/campo. Un dataset vacío ya no se ignora: no contiene datos válidos.
- Los errores de límites y dimensiones cambiaron de mensajes por rol (“chart/shape excede”) a validación de `x`, `y`, `w`, `h` y caja fuera del lienzo con contexto de slide/elemento. Se comprueban también tipo desconocido, propiedad desconocida, imagen fuera de data URL, imagen no decodificable y filas de tabla incompatibles.
- Se retiraron los casos de formato numérico `General`, conservación de `0.35`/`3.5`, “20 líneas caben”, chart junto al cuerpo, cero dimensión de líneas, shape de ancho de diapositiva, placements `y=2.5`/`y=4` y pares intencionales de shape/text con caja idéntica. Eran afirmaciones sobre la plantilla anterior o formatos internos de PptxGenJS; las pruebas nuevas cubren cajas exactas para los cinco tipos y datos de gráfico/tablas presentes en OOXML.
- El test de solapes dejó de rechazar el deck: informa pares con área de intersección positiva. El test de límites conserva el rechazo de una caja de entrada fuera del lienzo; otra tabla cuya altura real OOXML rebasa el borde se usa para probar el hecho `outside_slide` del informe.
- Se conserva la validación de skill bajo el límite del lector compartido y la verificación del artefacto/miniatura. Las pruebas de viewer HTML, navegación, contador, fallos de render y fallback siguen vigentes. El harness Puppeteer comprueba CSP, lectura allowlisted única del PPTX, ausencia de peticiones externas y captura de cuatro composiciones.

La compactación del manifiesto conserva los cinco tipos y exige `type`, `x`, `y`, `w`, `h`; las claves secundarias se validan con las listas del handler. El parser genérico de manifest acepta `enum` como palabra de JSON Schema para describir valores literales; no tiene ramas ni conocimiento de presentaciones. Las aserciones del contrato para el informe se migraron al shape compacto: `overflow:false` se omite, y caja, solapes o bounds se emiten solo cuando hay un hallazgo. Las pruebas siguen verificando boxes cuando hay overflow/solape/límite y comprueban explícitamente la omisión cuando el elemento está limpio; no se debilitó ni eliminó ningún check por este cambio de serialización.

El doble de Node proporciona anchos deterministas (`string.length × 8`) y no suplanta un canvas de fuentes del navegador; `metrics_source` refleja ese fallback. `composition-measurement-reports.json` está etiquetado como salida de ese doble y no es evidencia de medidas reales. La prueba instrumentada ejecuta el handler offscreen en el Android WebView y exige `canvas-font-metrics`, altura necesaria positiva, caja, overflow y contraste. El historial de renderizado Android y sus capturas queda en [pptx-viewer-eval/README.md](../pptx-viewer-eval/README.md).
