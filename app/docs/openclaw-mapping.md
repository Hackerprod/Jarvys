# Mapa de OpenClaw a Jarvys: agente personal

Estado de este documento: referencias y líneas OpenClaw verificadas; tabla actualizada con el estado de implementación Jarvys a 2026-10-15. La compilación y validación por impacto finalizaron en verde. El estado «pendiente» describe trabajo de Jarvys, no OpenClaw.

## Recorrido real de un turno en OpenClaw

1. El Gateway reúne el estado de sesión, las herramientas permitidas, las habilidades disponibles y los archivos del workspace configurado. `getOrLoadBootstrapFiles` refresca los archivos en cada turno y conserva la instantánea si el contenido no cambió (`src/agents/bootstrap-cache.ts:44-66`).
2. `buildAgentSystemPrompt` ensambla secciones con entradas explícitas; el runtime entrega las herramientas, contexto de workspace, modo de bootstrap, habilidades y estado de memoria (`src/agents/system-prompt.ts:283-349`). El renderer coloca contexto de workspace bajo Project Context y, según el modo, emite Memory Recall y Skills (`src/agents/system-prompt.ts:507-539`, `565-590`, `616-657`, `660-674`).
3. En un turno normal el agente decide, guiado por `AGENTS.md` y las instrucciones de memoria, si debe escribir un dato. OpenClaw no tiene una herramienta conversacional `memory_save` en Memory Core: expone `memory_search` y `memory_get` para leer; las instrucciones dirigen a escribir mediante la herramienta genérica `write` en los archivos del workspace (`extensions/memory-core/src/memory-tool-contract.ts:92-126`; `docs/reference/templates/AGENTS.md:43-71`; `docs/concepts/memory.md:35-54`).
4. Para recordar un dato en otra pregunta, Memory Recall instruye al modelo a buscar hechos previos que no estén en el contexto y a leer solo el fragmento necesario. El proveedor de memoria rinde esta sección solo si las herramientas están disponibles (`extensions/memory-core/src/memory-tool-contract.ts:133-160`; `src/agents/system-prompt.ts:527-539`).
5. Al alcanzar el mantenimiento previo a compactación, la ruta de mantenimiento llama `runMemoryFlushIfNeeded` antes de compactar (`src/agents/command/maintenance.ts:182-202`). Si corresponde, se crea una ejecución privada y separada sobre una vista acotada del transcript; su prompt pide anexar notas duraderas al archivo diario y devolver `NO_REPLY` si no hay nada que guardar (`extensions/memory-core/src/flush-plan.ts:15-37`, `63-107`; `src/auto-reply/reply/memory-flush-session.ts:43-89`).
6. La compilación del siguiente turno vuelve a cargar el bootstrap y a construir el prompt. La compactación persiste un resumen más el tramo reciente; la reinyección de secciones de `AGENTS.md` después de compactar es opcional, no la política general del perfil (`docs/reference/session-management-compaction/compaction.md:20-39`; `docs/concepts/system-prompt.md:164-198`; `src/agents/bootstrap-cache.ts:44-66`).

## Diferencias que se deben conservar al adaptar

- **Room en lugar de archivos Markdown:** OpenClaw organiza identidad, reglas y memoria como ficheros por workspace/agent y el modelo los lee/escribe con herramientas generales. Jarvys los almacena en la base Room que comparte con el ledger. El cambio de soporte preserva el flujo de decidir, escribir, comprobar y volver a inyectar, pero permite resultados de escritura con ID/revisión y transacciones/CAS.
- **Scopes:** OpenClaw es memoria de workspace por agente, con `USER.md` raíz compartido y, en Gateways multi-persona compatibles, un overlay `users/<profile-id>/USER.md` escogido por identidad autenticada (`docs/concepts/user-model.md:12-28, 57-90`). Jarvys usa explícitamente `user` global por defecto, además de `agent` y `conversation`. El modo privado/sin memoria bloquea leer o escribir el scope global. No trasladar IDs de persona o políticas de audiencia de OpenClaw al modelo de un solo dueño.
- **Sin multicanal:** las exclusiones de grupo/canal de OpenClaw protegen conversaciones compartidas. Jarvys no transporta canales; conserva tipos de sesión principal, subagente, tarea y proactivo, además del modo privado ya existente. Las reglas de memoria se deciden por tipo/scope, no por proveedor de chat.
- **Sin migración de `/memory/`:** esta integración empieza vacía. No ejecutar importadores, escaneos, lecturas ni borrados de los archivos antiguos.
- **Búsqueda:** OpenClaw actual usa recuperación semántica/híbrida; Jarvys usa solo FTS5 + BM25.
- **Afirmaciones verificables:** la regla genérica «afirmación final necesita evidencia» sí es OpenClaw; el detector post-turno de «guardado» sin resultado de escritura es una red nueva de Jarvys. No declarar que OpenClaw tenga ese detector.
- **Bootstrap:** el ritual real de OpenClaw elige identidad del agente; Jarvys necesita registrar cómo llamar al usuario para que su perfil personal funcione. Se adapta el ritmo no bloqueante y la verificación, no las preguntas literales.
- **Reinyección tras compactación:** OpenClaw compone de nuevo el prompt y refresca bootstrap en turnos normales; una reinyección específica de secciones de `AGENTS.md` tras compactar es opcional (`docs/reference/session-management-compaction/compaction.md:35`). Jarvys debe cumplir su requisito más fuerte de reconstruir perfil/reglas justo tras compactar, sin depender del resumen.
- **Snapshot al archivar:** OpenClaw no tiene un archivo snapshot separado para archivar un chat; Jarvys lo añade como red de preservación antes del archivado, usando el flujo privado de extracción y dejando intacta la transcripción. `newChat()` no borra la conversación anterior.
- **Archivos históricos retirados:** el checkout conserva constantes de compatibilidad de `TOOLS.md`, pero la política activa de nombres bootstrap es `AGENTS.md`, `SOUL.md`, `IDENTITY.md`, `USER.md`, `BOOTSTRAP.md` y `MEMORY.md` (`src/agents/workspace-bootstrap-policy.ts:10-38`). `TOOLS.md` y `HEARTBEAT.md` tienen documentación de retiro; no crear prompt de runtime basado en ellos.

## Hallazgos que podrían cambiar la spec

1. La versión actual de OpenClaw no tiene herramienta de memoria conversacional propia para escribir: usa herramienta genérica de archivos. El diseño de Jarvys con herramientas Room es una adaptación legítima del mecanismo al storage distinto.
2. OpenClaw no garantiza que todo hecho personal expuesto en una frase casual se escriba en ese turno. El prompt de workspace guía a guardar lo duradero y el usuario también puede pedir recordar; hay ingestión y consolidación posterior con filtros. La exigencia Jarvys de escribir en el mismo turno los datos personales declarados es más fuerte que su flujo default, y se cubre explícitamente con herramienta disponible + regla de perfil + validador de evidencia.
3. El flush precompactación es un turno oculto e independiente. Solo marca éxito cuando una herramienta de persistencia termina sin error o el agente responde `NO_REPLY` (nada que guardar); si falla, la compactación opcional continúa sin borrar el transcript. La spec de Jarvys debe modelar el resultado del flush como `saved / no-op / failed/skipped`, no como éxito implícito por haber invocado el modelo.
4. `/new`/`/reset` inyectan notas diarias recientes como contexto de arranque puntual; los turnos ordinarios no cargan todo el diario. El perfil y la capa curada sí son contexto de bootstrap cuando la sesión/política los permite.
5. El validador conversacional post-turno de Jarvys es deliberadamente una nueva garantía. OpenClaw únicamente implementa una regla de evidencia genérica en el prompt y verificación técnica de la persistencia de su tarea de flush.
