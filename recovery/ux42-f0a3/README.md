# UX42 F0a-3: compiled bindings and signed-scope disclosure

This closes current-runtime compiled-binding and approval-evidence gaps without exposing new capabilities. Production retains the six implemented capabilities, ten wire methods, schema/SDK v1, zero Android permissions and the existing launcher only. Additional typed construction nodes remain non-installable host fixtures. Activating them still requires a complete catalog/handler/policy/resource/approval slice.

## Compiled evidence

`TemplateApk` validates the complete ARSC envelope, actual package string-pool child boundaries, unique type specifications, historical-zero or current exact type chunk counts, alignment and bounds, unambiguous resource symbol identities, and nonoverlapping entry spans. Required drawable/factory_icon and xml/factory_backup_rules resolve by actual compiled ID/type/name to an existing file with exactly the accepted nodpi/default configuration. Backup XML content is independently audited. Unknown/sparse/compact layouts fail closed. Unrelated complex values receive structural size checks, not a full Android resource semantic audit.

`DexBindings` reads bounded DEX metadata without classloading or reflection. SHA-1 signature/Adler32 checksum, metadata tables/map/index bounds, bounded MUTF-8, class definition uniqueness and actual launcher/component-factory class definitions are required. Both required classes must be public/concrete, extend their expected Android class and declare a public no-argument constructor. Reference-only names or duplicate definitions do not satisfy the contract. These integrity checks are not authentication or a complete bytecode verifier; the authenticated template, exact complete DEX hashes/bytes, receipts and signing payload checks remain mandatory.

`ManifestInfo.resourceBindings` and `componentDex` are immutable derived evidence. Inspect and signing disclose them. They do not allow a project to register resources or handlers. Additional metadata construction references remain construction data and cannot enter the production closed plan.

## Last-signed scope

An additive, bounded snapshot inside the existing schema-v1 signing identity record anchors effective capabilities/permissions/exported components/features/queries/hosts to app ID, certificate, version and last APK hash. It is saved atomically at the existing signed-version reservation point, before publication. Approval distinguishes first signing, unchanged scope, additions/removals and unavailable legacy/missing/invalid baselines. A missing baseline never means no expansion. State comparison includes the record digest so a concurrent baseline edit invalidates approval. Publication uncertainty retains the signed version and snapshot; installed/published state is not inferred.

No portable key backup, new identity policy, actual installation, permission grant or external operation is introduced. Legacy receipts and identity records remain supported with explicit uncertainty. A new-key fingerprint exists only after its independently approved creation.

## Gates

Fresh focused and Full/Play/runtime aggregates use the reviewed per-worker offline guard; SDK tests, exact inherited-lint multiset comparison and unsigned Debug/Release builds remain required. Independent Python ARSC/DEX inspection and official aapt2/dexdump (when available), plus the existing AXML/apksigner/zipalign/payload audits inspect real generated artifacts. Test fixtures use ephemeral keys only in RAM. The separate D7 delivery is a test identity, not production.

Host validation is not physical Android, Keystore, WebView, installation/update, resource loading or data-retention acceptance. Conditional F0a work accompanies future handler slices; F0b/F0c/F1–F3 remain open. UX34 remains phase 0 with separate gates; UX43 remains last.
